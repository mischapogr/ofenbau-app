# 3D models for the planning explorer

`kachelofen-eckscheibe.glb` is a **placeholder**: a few boxes generated by
`npm run gen:model` (`scripts/generate-placeholder-model.mjs`) so the glTF stage
of `Planning3DExplorer` (orbit, auto-rotate, material variants, hotspots, AR)
works out of the box. It is not a real stove.

## Replacing it with a real model

1. Export the stove from CAD/Blender as **glTF binary (`.glb`)**, y-up, metres,
   origin on the floor, roughly `1.3 × 1.5 × 1.3 m` so the hotspot positions in
   `src/data/planning.js` stay plausible (or update them).
2. Put each cladding option on its own material and declare them as
   **`KHR_materials_variants`** (Blender: *Material Variants* panel of the glTF
   exporter). The variant names are what the explorer shows as material chips.
3. Compress before committing (target **< 3 MB**):
   ```bash
   npx @gltf-transform/cli optimize in.glb public/models/kachelofen-eckscheibe.glb \
     --compress meshopt --texture-compress ktx2
   ```
   `<model-viewer>` decodes Draco, meshopt and KTX2 textures on its own.
4. Keep `poster` in `planning.js` pointing at the matching render so the stage
   doesn't shift while the viewer loads.
5. Check the result in the explorer (`npm run dev` → "3D-Modell" button) and in
   the Playwright spec `tests/e2e/planning-explorer.spec.js`.

iOS Quick Look (AR) gets a USDZ generated on the fly by `<model-viewer>`; no
separate file is needed.
