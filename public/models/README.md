# 3D models for the planning explorer

`kachelofen-eckscheibe.glb` is generated by `npm run gen:model`
(`scripts/generate-stove-model.mjs`, no dependencies): a tiled corner stove with
heated bench, corner glass, firebox, cornice and flue, about 110 KB. It is a
procedural stand-in for a modelled or scanned stove, but it is built the way a
real export should be, so swapping it out changes nothing in the app.

## How the explorer uses it

- **One glTF material per part.** The stage (`src/components/planning/ExplorerStageModel.vue`)
  looks parts up by material name through `<model-viewer>`'s scene-graph API and
  applies the PBR factors (`color`, `roughness`, `metallic`) from
  `src/data/planning.js` → `model.parts[].options[]`. Any part combines with any
  other; `model.presets[]` are named combinations and `model.fire` holds the
  emissive factors behind the "Feuer an" toggle.
- Part names in the current model: `Kacheln`, `Putz` (joints), `Sockel`, `Sims`,
  `Auflage` (bench slab + cover plate), `Rahmen` (glass frame, knob, flue),
  `Glas`, `Feuerraum`, `Holz`, `Glut`.
- Hotspots (`model.hotspots[]`) are positions in model space (metres).

## Replacing it with a real model

1. Export the stove as **glTF binary (`.glb`)**, y-up, metres, origin on the
   floor under the body. The generated model spans roughly `x −1.5…0.5`,
   `y 0…2.0`, `z −0.5…0.5`; keep a similar footprint or update the hotspot
   positions and `camera-orbit` / `camera-target` in the stage.
2. Give every switchable part **its own material, named exactly like the `key`
   of a `parts[]` entry** (Blender: material name = part key). Parts that are
   not in `parts[]` keep their exported look. Textures are fine; the explorer
   only overrides the base-colour, roughness and metallic *factors*, so use
   neutral white textures for parts whose colour should be switchable.
3. Compress before committing (target **< 3 MB**):
   ```bash
   npx @gltf-transform/cli optimize in.glb public/models/kachelofen-eckscheibe.glb \
     --compress meshopt --texture-compress ktx2
   ```
   `<model-viewer>` decodes Draco, meshopt and KTX2 on its own.
4. Keep `poster` in `planning.js` pointing at the matching render so the stage
   doesn't shift while the viewer loads.
5. Re-render the 360° turntable from the new model: `npm run gen:turntable`.
6. Check the result in the explorer (`npm run dev` → "3D-Modell") and run
   `npx playwright test tests/e2e/planning-explorer.spec.js`.

iOS Quick Look needs a `.usdz`; set it via `ios-src` on the element when you
have one (the generated model ships without, so AR on iOS uses the WebXR path
where available).
